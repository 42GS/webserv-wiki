# webserv 평가표 정리

> 출처: <https://www.42evalhub.com/common/webserv> (42 EvalHub).
> 평가자는 1팀당 3명을 평가하며, 아래 항목을 순서대로 검토한다.
> 본 문서는 평가 항목을 한국어로 정리한 것이며, 모호한 부분은 원문(영문)을 그대로 병기한다.

## 0. Introduction (행동 강령)

- 평가 전 과정에서 정중·존중·건설적 태도를 유지한다.
- 학생/팀과 함께 발견한 문제를 토론하고 디버깅한다.
- 과제 해석에 차이가 있을 수 있음을 전제로 열린 태도로 채점한다.

## 0. Guidelines (절차 규칙)

- **Git 저장소에 제출된 코드만 평가한다.** 로컬 임시 파일·외부 링크는 무효.
- Git 저장소가 평가 대상 학생의 것이며, 올바른 프로젝트인지 확인. `git clone`은 빈 디렉토리에서 수행.
- 악의적인 alias로 평가자를 속이는지 점검.
- 채점 보조 스크립트가 있다면 함께 검토.
- **평가자가 해당 과제를 끝내지 못했다면, 평가 시작 전에 subject 전체를 읽어야 한다.**
- 빈 저장소·동작 불능·Norm 에러·치팅 등은 즉시 플래그 처리하고 평가 종료.
  - 일반 사유: 0점.
  - 치팅: -42점.
- **방어 도중 segfault, 예기치 않은/조기/제어되지 않은 종료가 발생하면 즉시 0점.** 적절한 플래그 사용.
- **설정 파일 외 어떤 파일도 수정해선 안 된다.** 수정이 필요하면 학생과 합의 후 명시적으로 진행.
- **메모리 누수 검사 필수.** heap 할당은 종료 전 모두 해제. `leaks`, `valgrind`, `e_fence` 등 사용 가능. 누수 발견 시 플래그 체크.

## 0. Attachments (자료)

평가 페이지에 첨부된 파일들:

- `subject.pdf` — 과제 명세서.
- `tester` / `ubuntu_tester` — 일반 테스터.
- `cgi_tester` / `ubuntu_cgi_tester` — CGI 전용 테스터.

## 1. Mandatory Part (필수 항목)

### 1.1 Check the code and ask questions

> 코드 검토와 질의응답. **이 단계에서 문제가 있으면 평가는 즉시 종료된다.**

- [ ] siege 설치 확인 (homebrew로 설치 시작).
- [ ] HTTP 서버의 기본 동작 설명을 요청.
- [ ] **I/O Multiplexing에 어떤 함수를 사용했는지** 묻기.
- [ ] `select()` (또는 동등 함수)가 어떻게 동작하는지 설명 요청.
- [ ] **`select()` 한 개만 사용**했는지, 그리고 accept / read / write를 어떻게 관리하는지 묻기.
- [ ] **`select()`(또는 동등 함수)는 메인 루프에 있어야 하며, read·write FD를 동시에(AT THE SAME TIME) 검사해야 한다.**
  - 그렇지 않으면 **0점, 평가 종료.**
- [ ] **클라이언트당 select()당 read 1번 또는 write 1번만 수행해야 한다.** select()부터 read/write까지의 코드를 직접 보여달라고 요청.
- [ ] 모든 socket의 `read`/`recv`/`write`/`send` 호출에 대해, **에러 반환 시 클라이언트가 제거**되는지 확인.
- [ ] 반환값 검사 점검:
  - **`-1` 또는 `0`만 검사하는 것은 부족.** 둘 다(both) 검사해야 한다.
- [ ] **`read`/`recv`/`write`/`send` 이후 `errno`를 검사하면 0점, 평가 종료.**
- [ ] **`select()`(또는 동등 함수)를 거치지 않고 어떤 FD에 read/write하는 것은 엄격히 금지.**
- [ ] **재링크(re-link) 이슈 없이 컴파일** 되어야 한다. 안 되면 'Invalid compilation' 플래그.
- [ ] 위 항목 중 하나라도 불명확하거나 부정확하면 평가 중단.

### 1.2 Configuration

> 설정 파일에서 다음 동작이 가능한지 확인하고 결과를 테스트.

- [ ] **HTTP 응답 상태 코드 목록**을 인터넷에서 검색해 둘 것. 이 평가 동안 잘못된 status code가 나오면 해당 항목 점수를 주지 말 것.
- [ ] 다른 포트로 여러 서버 설정.
- [ ] 다른 호스트네임으로 여러 서버 설정.
  ```bash
  curl --resolve example.com:80:127.0.0.1 http://example.com/
  ```
- [ ] 기본 에러 페이지 설정 (404 페이지 변경 시도).
- [ ] 클라이언트 바디 크기 제한.
  ```bash
  curl -X POST -H "Content-Type: plain/text" \
       --data "BODY IS HERE write something shorter or longer than body limit"
  ```
- [ ] 같은 서버 내에서 라우트별로 다른 디렉토리 매핑.
- [ ] 디렉토리 요청 시 검색할 기본 파일 설정 (index).
- [ ] 라우트별 허용 메서드 설정. 예) DELETE 권한 있는/없는 경우 모두 시도.

### 1.3 Basic checks

> telnet, curl, 준비된 파일을 사용해 다음 기능이 정상 동작함을 시연.

- [ ] **GET, POST, DELETE** 요청이 정상 동작.
- [ ] **알 수 없는(UNKNOWN) 요청**도 크래시 없이 처리.
- [ ] 모든 테스트에서 **올바른 status code**를 반환.
- [ ] 서버에 파일을 업로드하고 다시 다운로드.

### 1.4 Check CGI

> 다음 사항에 주의:

- [ ] CGI를 통해 서버가 정상 동작.
- [ ] **CGI는 스크립트가 위치한 디렉토리(올바른 working directory)에서 실행**되어야 상대 경로 파일 접근이 가능.
- [ ] 학생의 도움을 받아 모든 동작 검증. **`GET`과 `POST`** 메서드 모두 테스트.
- [ ] **에러를 포함한 파일로 에러 처리 검증.**
  - 무한 루프 스크립트, 에러 발생 스크립트 등 사용 가능. 학생이 도와주어야 함.
- [ ] **서버는 어떤 경우에도 크래시되지 않아야 하며, 문제 발생 시 에러가 가시적으로 보여야 한다.**

### 1.5 Check with a browser

- [ ] 팀이 정한 기준 브라우저 사용. 네트워크 탭을 열고 서버에 접속.
- [ ] **request header / response header** 확인.
- [ ] **완전한 정적 웹사이트 서빙**과 호환되어야 함.
- [ ] 잘못된 URL 시도.
- [ ] 디렉토리 리스팅 시도.
- [ ] 리다이렉트 URL 시도.
- [ ] 임의의 추가 테스트 시도.

### 1.6 Port issues

- [ ] 설정 파일에서 여러 포트로 다른 사이트 띄우고, 브라우저로 올바른 사이트가 뜨는지 확인.
- [ ] **같은 포트를 여러 번 설정**해보기 → 동작하면 안 됨.
- [ ] **공통 포트를 가진 서로 다른 설정의 서버를 동시에 실행**.
  - 동작하면 학생에게 "왜 한 설정이 깨져 있는데도 서버가 돌아가야 하는가" 묻고 계속 진행.

### 1.7 Siege & stress test

- [ ] **Siege로 스트레스 테스트** 실행.
- [ ] 빈 페이지에 `siege -b`를 돌렸을 때 **availability ≥ 99.5%**.
- [ ] 메모리 누수가 없어야 함 (프로세스 메모리가 무한 증가하지 않는지 모니터).
- [ ] 행(hanging) 상태 연결이 없어야 함.
- [ ] **서버 재시작 없이 siege를 무한히 돌릴 수 있어야 한다** (`siege -b` 기준).

## 2. Bonus part (보너스)

> ⚠️ **필수 항목이 전부 완벽하게 통과**되고 에러 처리가 제대로 동작하는 경우에만 평가한다.
> 필수에서 하나라도 통과하지 못했다면 보너스 점수는 **전부 무시**한다.

### 2.1 Cookies and session

- [ ] 웹서버에 쿠키와 세션 시스템이 정상 동작.

### 2.2 CGI

- [ ] CGI 시스템이 **하나 이상**(예: PHP, Python 등 복수) 동작.
