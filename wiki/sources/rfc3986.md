# RFC 3986 — Uniform Resource Identifier (URI): Generic Syntax

원본: `raw/rfc3986.txt`. rfc-editor.org에서 받은 원문 그대로다 (2026-10-15).
2005년 1월에 나온 인터넷 표준(STD 66)이다. RFC 2396 등을 대체한다 (raw/rfc3986.txt:7-16).

## 과제와 관련된 절

|---|---|---|
| 2.1~2.4 (634) | percent-encoding, 예약·비예약 문자, 디코딩 시점 | [[concepts/security]] |
| 3.3 Path (1199), 3.4 Query (1279) | 경로와 query의 경계, dot-segment | [[concepts/request-parsing]], [[concepts/security]] |
| 5.1.3 (1638), 5.2.3 Merge Paths (1777) | 기준 URI, 상대 경로 병합 | [[concepts/configuration-file]] |
| 5.2.4 Remove Dot Segments (1805), 5.4 예시 (1948) | `.`·`..` 제거 알고리즘 | [[concepts/security]] |
| 6.2.2.2 (2228), 6.2.2.3 (2247) | percent-encoding·경로 세그먼트 정규화 | [[concepts/security]] |

다루지 않는 절: scheme·authority·host 세부 문법(3.1~3.2), fragment, IANA, 부록.

## 핵심

- `%2E`는 비예약 문자 `.`에 해당하므로 `%2e%2e`는 `..`과 동등하다 (raw/rfc3986.txt:735-743).
- component를 먼저 나눈 뒤 디코딩하고, 보안 검사는 디코딩 후에 한다 (raw/rfc3986.txt:2439-2443).
- 같은 문자열을 두 번 디코딩하면 안 된다 (raw/rfc3986.txt:767-771).
- 상대 경로는 기준 URI 경로의 마지막 세그먼트를 뺀 부분에 붙는다 (raw/rfc3986.txt:1799-1803).
