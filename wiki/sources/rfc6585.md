# RFC 6585 — Additional HTTP Status Codes

원본: `raw/rfc6585.txt`. rfc-editor.org에서 받은 원문 그대로다 (2026-10-15).
2012년 4월에 나온 IETF Standards Track 문서다 (raw/rfc6585.txt:7-11). 428·429·431·511 status code를 정의한다. RFC 9110도 용량 제한 관련 코드는 이 문서에 정의되어 있다고 한다 (raw/rfc9110.txt:8626-8629).

## 과제와 관련된 절

| 절 (시작 줄) | 내용 | 위키 페이지 |
|---|---|---|
| 1 Introduction (77) | 이 코드들은 선택 사항. 모르는 코드는 같은 계열의 일반 에러로 처리됨 | [[concepts/status-codes]] |
| 5 431 (175) | 헤더 필드가 너무 커서 거부 | [[concepts/status-codes]], [[concepts/request-parsing]] |
| 7 Security Considerations 중 7.3 431 (304) | 공격 중이면 431 대신 연결을 끊어도 됨 | [[concepts/security]] |

다루지 않는 절: 428(조건부 요청), 429(rate limiting), 511(captive portal).

## 핵심

- 이 문서의 코드는 선택 사항이라 서버에 지원을 요구할 수 없다. 모르는 코드를 받은 클라이언트는 같은 계열의 일반 에러로 처리한다 (예: 499 → 400) (raw/rfc6585.txt:83-87).
- 431: 헤더 필드가 너무 커서 처리를 거부한다. 크기를 줄여 다시 보낼 수 있다 (raw/rfc6585.txt:177-179).
- 헤더 **전체**가 클 때와 **한 필드**가 클 때 모두 쓴다. 한 필드가 원인이면 응답 본문에 어느 필드인지 적는다 (SHOULD, raw/rfc6585.txt:181-184).
- 431 응답은 캐시에 저장하면 안 된다 (raw/rfc6585.txt:201).
- 431은 필수가 아니다. 공격을 받는 중이면 그냥 연결을 끊는 편이 나을 수 있다 (raw/rfc6585.txt:306-308).
