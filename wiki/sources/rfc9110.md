# RFC 9110 — HTTP Semantics

원본: `raw/rfc9110.txt`. rfc-editor.org에서 받은 원문 그대로다 (2026-10-15).
2022년 6월에 나온 IETF 표준(STD 97)이다. RFC 7231 등을 대체한다 (raw/rfc9110.txt:6-11, raw/rfc9110.txt:27-28).
버전과 무관한 HTTP 의미론을 다룬다 (raw/rfc9110.txt:19-23). 메시지 문법(파싱, chunked)은 RFC 9112 소관이다 → [[source-wishlist]].

## 핵심 규칙

- 범용 서버는 GET과 HEAD를 MUST로 지원한다. 나머지 메서드는 OPTIONAL (raw/rfc9110.txt:3794-3795).
- 모르거나 구현하지 않은 메서드는 501, 알지만 대상 리소스에 허용되지 않은 메서드는 405 (SHOULD, raw/rfc9110.txt:3799-3804).
- 메서드 토큰은 대소문자를 구분한다 (raw/rfc9110.txt:3748).
- 405 응답에는 `Allow` MUST (raw/rfc9110.txt:4724-4726, raw/rfc9110.txt:7605-7607).
- reason phrase는 권장일 뿐이다. 바꾸거나 빼도 프로토콜에 영향이 없다 (raw/rfc9110.txt:6841-6844).

## 과제 문서와의 충돌·질문
